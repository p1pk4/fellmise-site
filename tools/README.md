# tools/ — генератор и обработка арта сайта

Все генерации идут на **боевом пресете** `pixelart-pipeline/workflows/objects_battle_v1.json`
(FLUX.1-dev fp8 + `fellmise_objects_v1` @0.7, без blue2d, euler/simple, 20 шагов,
guidance 3.5, cfg 1.0, 1024²). Граф загружается из файла и проверяется ассертами —
пресет нельзя случайно сдвинуть, отредактировав скрипт.

## Правила промптов

**Шаблон:** `fllmse style, <объект>, game asset, top-down view, plain gray background`

### ⚠️ Анти-штамп (главное правило)

Модель охотно скатывается в узнаваемые генеративные клише. Такой кадр технически
чистый, но сразу читается как «сделано нейросетью». **Предметы должны лежать так,
как их оставил бы человек**, а не так, как их рисует стоковая иллюстрация.

Запрещённые формулировки и мотивы:

| Штамп | Вместо него |
|---|---|
| топор **воткнут** в пень | топор **прислонён** к пню, щепа вокруг |
| меч **в камне** | меч у стены, на стойке, в ножнах |
| **горящая** книга, книга с огнём | раскрытая книга, светящиеся руны |
| **светящиеся глаза** у предметов | свет из окна, из щели, от углей |
| предмет **парит** в воздухе | предмет стоит на земле |
| симметричная **композиция-эмблема** | смещённый центр, случайный поворот |

Практика: если после 4 сидов модель упорно даёт штамп — не бороться промптом,
а **убрать сам предмет** из сцены (пример: `biome_stump` — если топор всё равно
втыкается, просить пень со щепой без топора).

### Прочее

- Множественное число («rune stone**s**») даёт несколько объектов и роняет
  фильтр по критерию «один связный объект» — это нормально, решается
  `GATE_OVERRIDE` в финишере, но лучше формулировать в единственном числе,
  если нужен один предмет.
- Цветовой якорь помогает материалу читаться: `iron ore chunk` дал серый
  камень на всех сидах, `iron ore chunk with rusty orange-brown metallic veins` —
  железо. Если материал не читается, добавить цвет.
- Экзотика вне охвата LoRA v1 (существа, персонажи, UI-иконки с сеткой) не
  генерируется — слоты ждут датасета v2.

## Пайплайн

```
gen_batch*.py      генерация кадров          -> out/site_assets/_raw/<id>/
finish_batch*.py   фильтр, пик, вырез        -> out/site_assets/final/<id>.png
fix_holes.py       замкнутые области фона    -> перезапись final/
grade_sprites.py   дефринж + общий грейд     -> out/site_assets/final_web/
export_web.py      WebP+PNG по ролям         -> assets/
build_site.py      index.html + ru/index.html
review_sheets.py   листы визуальной приёмки  -> out/site_assets/review_sheet_*.png
```

**Финишеры намеренно поштучные.** Полный прогон `filter_site_pack.py` пересобрал бы
каждый финал по резкости и откатил бы уже сделанное: выбитые дыры, перегенерации
(`res_iron`, `res_wood`, `feat_skills`, `feat_craft`) и пики по типу.

**Тайлы — не объекты.** У `ground_*` и `road_segment` вырез флуд-филлом отключён:
кадр нужен целиком, иначе текстуру вырежет из самой себя.

## Приёмка

Годность кадра — флуд-филл из углов (заливка ≥15%, один связный объект, ≤2 края),
метрика импортируется из `pixelart-pipeline/scripts/acceptance_metrics.py`, а не
переписывается здесь.

Резкость (`sharpness`) — только тайбрейк между годными кадрами. Она ранжирует
контур и **не видит, тот ли это объект**: на этом паке она уже выбирала топор
вместо кирки, арбалет вместо лука и горящую книгу вместо книги с рунами. Поэтому
финальный выбор — визуальный, а пик фиксируется в `PICKS`/`PICK_OVERRIDE` с
причиной.
